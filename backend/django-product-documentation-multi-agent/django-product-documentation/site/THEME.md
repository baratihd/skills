# قرارداد پوسته مستندات

پوسته بر Material for MkDocs نسخه نصب‌شده 9.7.7 استوار است. `theme.css` متغیرهای طراحی، تایپوگرافی، چیدمان و اجزا را تعریف می‌کند؛ `rtl.css` فقط جهت صفحه و literal را کنترل می‌کند. انتخاب ظاهر، جست‌وجو، کپی code و ناوبری موبایل از Material هستند. انتخاب مستقل فونت با اسکریپت کوچک محلی `javascripts/fonts.js` و کنترل‌های استاندارد HTML انجام می‌شود؛ وابستگی JavaScript تازه‌ای اضافه نشده است.

## توسعه و بررسی سریع

```bash
make -C docs serve
make -C docs check
make -C docs check-theme
```

دستور آخر اختیاری و مخصوص پوسته است؛ Node 22 یا جدیدتر و Chrome محلی نیاز دارد. `CHROME=/path/to/chrome make -C docs check-theme` مسیر مرورگر را عوض می‌کند. هیچ بسته npm یا مرورگر دانلود نمی‌شود. آزمون یک سرور ایستای موقت روی loopback و پروفایل موقت Chrome می‌سازد، درخواست‌های غیرمحلی را مسدود می‌کند، سپس هر دو را می‌بندد. برای مسیر نماینده متفاوت، `THEME_FA_PAGE=/product/` و `THEME_EN_PAGE=/technical/` را تعیین کنید؛ صفحه انگلیسی باید نمونه code داشته باشد. `THEME_SITE_DIR` پوشه خروجی ایستای جایگزین و `THEME_COMPONENTS_PAGE` مسیر fixture موقت را تعیین می‌کند. نتیجه و screenshotها در `.automation/theme-check/` می‌مانند؛ در Git نیستند. screenshotها را پس از هر تغییر بصری واقعاً مشاهده کنید؛ موفقیت assert به‌تنهایی بازبینی بصری نیست.

## انتخاب ظاهر

کلید سربرگ سه حالت را به ترتیب **سیستم ← روشن ← تیره ← سیستم** عوض می‌کند؛ آیکن و label، حالت فعلی و انتخاب بعدی را مشخص می‌کنند. انتخاب اول سیستم است. Material انتخاب را در localStorage با دامنه ریشه سایت ذخیره می‌کند و در حالت سیستم، تغییر OS را زنده دنبال می‌کند. برای بازگشت به تنظیم خودکار، کلید را تا آیکن سیستم بزنید. صفحه را می‌توان با Tab پیمود و روی کنترل ظاهر Enter زد.

رنگ‌ها با متغیرهای `--docs-*` تعریف شده‌اند و به متغیرهای Material نگاشت می‌شوند. متغیرهای تیره یک بار در selector حالت slate و یک بار در media query اولین بازدید تکرار می‌شوند؛ هنگام تغییر رنگ آن‌ها را هماهنگ نگه دارید. media query فقط پیش از تنظیم palette توسط Material و در حالت بدون JavaScript استفاده می‌شود تا اولین بازدید تیره، زمینه روشن نداشته باشد. انتخاب ذخیره‌شده از اسکریپت آغازین خود Material اعمال می‌شود.

## زبان، چیدمان و فونت

- ناوبری سایت فارسی است؛ در نمایش سه‌ستونه، ناوبری چپ و فهرست سرفصل راست قرار می‌گیرد. متن هر صفحه جهت مستقل دارد. ناوبری موبایل همچنان رفتار بومی RTL دارد.
- `hooks.py` به technical/quality پوشش `lang="en" dir="ltr"` و به سایر صفحات `lang="fa" dir="rtl"` می‌دهد. این قرارداد برای validator هم استفاده می‌شود.
- code، JSON، SQL، فرمان، مسیر API و Mermaid باید LTR باشند؛ برای literalها در Markdown از backtick استفاده کنید. خود جدول جهت زبان صفحه را حفظ می‌کند و به صورت افقی قابل پیمایش است.
- پیش‌فرض فارسی Vazirmatn و انگلیسی Inter است؛ از دکمه «تنظیم فونت» در سربرگ می‌توان فارسی را به Amiri یا B Nazanin و انگلیسی را به Times New Roman تغییر داد. فایل‌های Vazirmatn و Inter و Amiri اکنون با مجوز OFL دانلود و در assets/fonts میزبانی می‌شوند؛ انتخاب آن‌ها به نصب دستگاه وابسته نیست. نام CSS به‌تنهایی شاهد بارگذاری نیست؛ آزمون مرورگر فونت مصرف‌شده برای glyphها را هم بررسی می‌کند.
- JetBrains Mono Regular همراه مجوز OFL از منبع محلی کپی شده و در `content/assets/fonts/` با `font-display: swap` میزبانی می‌شود؛ حدود 113 KiB، فقط یک وزن. فونت بیرونی/Google Fonts غیرفعال است.
- برای میزبانی فونت‌های دیگر، فایل WOFF2 دارای مجوز و مجوز توزیع را در همین پوشه قرار دهید، `@font-face` هم‌نام با یک وزن متغیر یا وزن‌های محدود تعریف کنید و مسیر را نسبت به CSS بنویسید. سپس check-theme، صفحه فارسی/انگلیسی و تغییر چیدمان هنگام بارگذاری را بررسی کنید. فونت تجاری frontend را بدون مجوز کپی نکنید.

## تنظیم فونت برای خواننده و نگهدارنده

دکمه آیکن فونت در سربرگ دو انتخاب مستقل «فونت فارسی» و «فونت انگلیسی» دارد. تغییر فوری است؛ متن فارسی و پوسته از انتخاب فارسی و صفحات technical/quality از انتخاب انگلیسی پیروی می‌کنند. فونت code مستقل می‌ماند. «بازگشت به پیش‌فرض» هر دو انتخاب را بازمی‌گرداند. منو با صفحه‌کلید باز می‌شود و Escape آن را می‌بندد.

انتخاب‌ها فقط در localStorage همان ریشه سایت، با کلید منتهی به `:documentation-fonts` و فقط به صورت شناسه ذخیره می‌شوند؛ نه روی سرور و نه حساب کاربر. در بارگذاری بعدی پیش از نمایش محتوا اعمال می‌شوند. در صورت مسدود بودن ذخیره مرورگر، انتخاب در همین صفحه کار می‌کند و پیام عدم امکان ذخیره نمایش داده می‌شود. انتخاب خراب یا حذف‌شده از پیکربندی به پیش‌فرض برمی‌گردد. بدون JavaScript، پیش‌فرض CSS نمایش داده می‌شود.

**فایل تنظیمات:** `extra.documentation_fonts` در `mkdocs.yml`. برای هر زبان، `label`، `default` و فهرست `options` دارد؛ هر گزینه شامل `id` پایدار، `label` نمایشی، `family` معتبر CSS و `font_names` (نام واقعی خانواده و aliasهای همان فونت، بدون نام fallback) است. این نام‌ها برای بررسی بارگذاری فایل یا وجود نصب محلی استفاده می‌شوند. برای تغییر گزینه‌ها این بخش را ویرایش کنید؛ `default` باید یکی از IDهای همان زبان باشد. حذف گزینه باعث بازگشت انتخاب قدیمی آن به پیش‌فرض می‌شود. در صورت تغییر خانواده پیش‌فرض، fallbackهای `--docs-font-fa` و `--docs-font-en` در ابتدای theme.css را نیز برای حالت بدون JS هماهنگ کنید.

Vazirmatn متغیر، Inter متغیر و Amiri Regular/Bold از Google Fonts با OFL دانلود و همراه متن مجوز میزبانی می‌شوند؛ JetBrains Mono نیز همان فایل محلی قبلی است. منبع، اندازه و SHA-256 در `evidence/font-assets.json` ثبت است. فونت هنگام نمایش سایت از CDN دریافت نمی‌شود.

B Nazanin و بسته اصلی times32.exe نیز به درخواست کاربر در `.automation/font-downloads/` دانلود شدند، اما این پوشه ignored و خارج از سایت منتشرشونده است. installer اجرا نشده و فونتی روی سیستم نصب نشده است. برای B Nazanin مجوز معتبر توزیع وب پیدا نشد؛ [FAQ بسته Microsoft](https://corefonts.sourceforge.net/faq8.htm) بازتوزیع را به بسته اصلی محدود می‌کند و مجوز عمومی سرو فایل TTF به عنوان وب‌فونت نمی‌دهد. این دو گزینه فعلاً فقط از نصب موجود دستگاه استفاده می‌کنند؛ برای یکسان بودن نمایش، فایل با مجوز میزبانی وب لازم است. مجوز یک repository یا برچسب «دانلود رایگان» به‌تنهایی مجوز فایل فونت نیست.

پس از انتخاب، هر زبان وضعیت بارگذاری مستقل دارد. اگر نه فایل بارگذاری شود و نه نسخه محلی قابل استفاده باشد، پیام «بارگذاری نشد؛ فونت جایگزین نمایش داده می‌شود» کنار همان انتخاب می‌آید. انتخاب ذخیره می‌ماند تا پس از فراهم‌شدن فونت قابل استفاده باشد؛ انتخاب در منو به معنی موفقیت بارگذاری نیست. بررسی وضعیت فقط خانواده درخواستی/aliasهای آن را می‌سنجد، نه fallback را. پاسخ قدیمی بررسی نمی‌تواند پیام انتخاب جدید را عوض کند.

وراثت `--md-text-font-family` برای هر صفحه هم تنظیم شده است تا aside، input و سایر اجزایی که Material به آن‌ها font-family صریح می‌دهد، زبان همان صفحه را رعایت کنند. فهرست سرفصل صفحه انگلیسی نیز فونت انگلیسی دارد؛ code همچنان مستقل است.

قالب UI در `overrides/main.html` و `overrides/partials/font-settings.html` است. main از base خود Material ارث می‌برد؛ کپی سربرگ یا منطق palette نگه‌داری نمی‌کنیم. اسکریپت فقط شناسه‌های موجود در پیکربندی را به family تبدیل می‌کند؛ داده ذخیره‌شده به عنوان CSS/HTML اجرا نمی‌شود.

## اجزای قابل استفاده

عنوان و متن هر component زبان همان پوشه را رعایت می‌کند. وضعیت را همیشه **با متن** مشخص کنید؛ رنگ به‌تنهایی معنی ندارد. کلاس‌های `verified`، `inferred`، `missing`، `deprecated` و `breaking` به‌ترتیب برای تأیید، استنباط، فقدان شاهد، کنارگذاری و تغییر ناسازگار آماده‌اند. استفاده از آن‌ها سطح اطمینان ادعا را تغییر نمی‌دهد.

````markdown
!!! verified "تأییدشده از کد"
    رفتار محدود و شاهد واقعی آن را بنویسید.

!!! inferred "استنباطی — نیازمند تأیید"
    مرز استنباط، سؤال مشخص و شاهد مفقود را بنویسید.

!!! missing "شاهد موجود نیست"
    سؤال و سند/آزمون مورد نیاز را ثبت کنید.

!!! deprecated "خارج از دامنه جاری"
    مرجع تصمیم کاربر و وضعیت تاریخی را مشخص کنید.

!!! breaking "تغییر ناسازگار"
    اثر بر مصرف‌کننده و مسیر مهاجرت تأییدشده را بنویسید.

=== "Request"

    ```json
    {"example": "synthetic"}
    ```

=== "Response"

    ```json
    {"result": "illustrative"}
    ```

- [ ] بررسی شاهد
- [x] حفظ شناسه‌های قبلی
````

برای component در technical/quality عنوان‌ها و روایت نمونه بالا را انگلیسی بنویسید. جدول استاندارد Markdown، نقل‌قول، فهرست و headingها خودکار سبک می‌گیرند؛ wrapper تازه نسازید. headingهای BR/TEST و جدول coverage از همین اجزا استفاده می‌کنند. Mermaid در CSS از نظر جهت و ظرف پشتیبانی می‌شود، اما renderer محلی موجود نیست و در صفحات فعلی fence از نوع mermaid نداریم؛ **رندر نمودار آزمایش نشده است**. تا renderer محلی و دارای مجوز اضافه و بررسی نشده، افزونه‌ای که Mermaid را از CDN می‌گیرد فعال نکنید.

## بررسی‌های پیش از تحویل

- `make check`: ساخت strict، لینک، nav، ID، زبان، شواهد و wrapper.
- `make check-theme`: حالت‌ها، سیستم زنده، انتخاب دستی، ماندگاری، جهت، ستون‌ها، اندازه desktop/tablet/mobile، کنترل ظاهر با صفحه‌کلید، جست‌وجوی انگلیسی، کپی، فونت code، فونت واقعی glyphها با CDP، وراثت اجزای فرزند انگلیسی، پیام فونت ناموجود با fixture قطعی، انتخاب مستقل فارسی/انگلیسی، ماندگاری و reset فونت، منوی موبایل/کیبورد، کنتراست tokenها، کاهش حرکت و خطای asset/درخواست بیرونی.
- بازبینی screenshot فارسی و انگلیسی در روشن و تیره؛ بررسی متون ترکیبی، table و code در صفحه واقعی. آیکن/label و Tab را نیز کنترل کنید.
- assert کنتراست، ممیزی کامل WCAG 2.2 AA یا آزمون با screen reader نیست. عملکرد، CLS و همه رنگ‌های syntax highlighting به صورت جامع اندازه‌گیری نشده‌اند. جست‌وجوی فارسی stemming تضمین‌شده ندارد.

## نگهداری اسکیل

scaffold پوسته و این راهنما در `django-product-documentation/site/` همان اسکیل نگه‌داری می‌شوند. وقتی قرارداد طراحی تغییر می‌کند، فایل پیکربندی، CSS، فونت دارای مجوز و راهنمای آن را در scaffold هم هماهنگ کنید. صفحه‌های محتوای این پروژه را روی scaffold اسکیل کپی نکنید. وابستگی یا JS تازه فقط برای نیازی که Material موجود پاسخ نمی‌دهد اضافه شود.

فایل‌های اسکیل در `.codex/skills/` این مخزن ignored هستند؛ تغییر اسکیل فعلاً محلی است و در diff عادی Git دیده نمی‌شود. برای انتقال اسکیل، خود پوشه آن را نیز در بسته/مخزن مجاز نگه‌داری کنید.

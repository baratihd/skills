# Agent-neutral invocation guide

Read `SKILL.md` and relevant `references/` before operating. Use `site/` only as the MkDocs starting scaffold, not as proof of project behavior.

## Typical request

Use the `django-product-documentation` skill. Document the specified Django app or feature from verified repository source and existing docs. Preserve the language rules (Persian/RTL Product + Business; English/LTR Technical + Quality). Generate test specifications rather than executable tests unless requested; update affected docs only and report evidence, gaps, and build-check results.

## Portability

The same instructions apply to Codex, OpenCode and Claude Code. If an optional tool is unavailable, follow the skill's evidence-based fallback process and report what could not be inspected or verified.
